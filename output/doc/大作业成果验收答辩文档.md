## 五、代码结构讲解

### 1. 启动类

文件：

```text
src/main/java/org/example/BigWorkApplication.java
```

作用：

- 启动 Spring Boot 项目。
- 扫描 Controller、Service、Mapper 等组件。
- 让项目以内置 Tomcat 方式运行。

答辩话术：

“这个类是项目入口，运行它以后 Spring Boot 会加载配置、启动 Web 服务，并扫描项目中的控制器、服务类和 Mapper。”

### 2. 实体类 User

文件：

```text
src/main/java/org/example/bigwork/entity/User.java
```

字段：

- `id`：用户编号。
- `username`：用户名。
- `password`：密码。
- `realName`：真实姓名。
- `studentNo`：学号。

答辩话术：

“User 实体类和数据库 users 表对应，用来在 Java 程序中保存一条用户数据。”

### 3. Controller 层

文件：

```text
src/main/java/org/example/bigwork/controller/UserController.java
```

主要接口：

- `GET /bigwork/login`：进入登录页面。
- `POST /bigwork/login`：处理登录请求。
- `GET /bigwork/register`：进入注册页面。
- `POST /bigwork/register`：处理注册请求。
- `GET /bigwork/users`：查看用户列表。
- `POST /bigwork/users/update`：修改用户信息。
- `GET /bigwork/users/delete`：删除用户。
- `GET /bigwork/logout`：退出登录。

答辩话术：

“Controller 层主要负责接收浏览器请求，调用 Service 层处理业务，然后决定返回哪个 JSP 页面或者重定向到哪个地址。”

### 4. Service 层

文件：

```text
src/main/java/org/example/bigwork/service/UserService.java
```

主要方法：

- `register`：注册用户，检查用户名和密码是否为空，检查用户名是否重复。
- `login`：根据用户名和密码查询用户。
- `listUsers`：查询全部用户。
- `update`：根据 ID 修改用户。
- `delete`：根据 ID 删除用户。

答辩话术：

“Service 层负责业务判断，比如注册时不能用户名为空，也不能用户名重复。这样 Controller 不需要直接写太多业务逻辑，结构会更清晰。”

### 5. Mapper 层

文件：

```text
src/main/java/org/example/bigwork/mapper/UserMapper.java
src/main/resources/mapper/UserMapper.xml
```

作用：

- Java 接口定义数据库操作方法。
- XML 文件编写具体 SQL。
- MyBatis 负责把接口方法和 SQL 语句对应起来。

答辩话术：

“Mapper 层就是 Java 程序和数据库之间的桥梁。比如 `findAll` 对应查询所有用户的 SQL，`insert` 对应新增用户的 SQL。”

### 6. JSP 页面

主要页面：

```text
src/main/webapp/WEB-INF/views/bigwork/login.jsp
src/main/webapp/WEB-INF/views/bigwork/register.jsp
src/main/webapp/WEB-INF/views/bigwork/users.jsp
```

作用：

- `login.jsp`：登录页面。
- `register.jsp`：注册页面。
- `users.jsp`：用户管理页面。

答辩话术：

“JSP 页面负责展示数据和提交表单。比如用户列表页面通过 JSTL 的 `c:forEach` 遍历后端传来的用户集合，把每个用户显示在表格里。”

## 六、一次请求的执行流程

以登录为例：

1. 浏览器打开登录页。
2. 用户输入用户名和密码。
3. 表单提交到 `/bigwork/login`。
4. `UserController.login` 接收请求。
5. Controller 调用 `UserService.login`。
6. Service 调用 `UserMapper.findByUsernameAndPassword`。
7. MyBatis 执行 SQL 查询 MySQL。
8. 如果查到用户，把用户对象放入 Session。
9. 页面重定向到 `/bigwork/users`。
10. 用户列表页查询全部用户并展示。

可以用一句话总结：

“浏览器请求先到 Controller，Controller 调 Service，Service 调 Mapper，Mapper 通过 MyBatis 操作 MySQL，最后结果再回到 JSP 页面展示。”

## 七、老师可能问的问题与回答策略

### 1. 你这个系统实现了哪些功能？

回答：

“主要实现了用户管理的基础 CRUD 功能，包括注册、登录、查询用户列表、修改用户信息、删除用户和退出登录。登录后才能进入用户管理页面，未登录访问会跳回登录页。”

### 2. 什么是 CRUD？

回答：

“CRUD 是增删改查的意思。Create 是新增，比如注册用户；Read 是查询，比如查看用户列表；Update 是修改，比如修改姓名和学号；Delete 是删除，比如删除测试用户。”

### 3. 为什么使用 Spring Boot？

回答：

“Spring Boot 可以简化 Java Web 项目的配置，内置 Tomcat，启动比较方便。我这个项目用它来启动 Web 服务、加载配置、管理 Controller 和 Service 等组件。”

### 4. Spring MVC 在项目里做了什么？

回答：

“Spring MVC 主要负责处理浏览器请求。比如用户提交登录表单后，请求会进入 `UserController`，Controller 根据请求路径调用对应方法，然后返回 JSP 页面或重定向地址。”

### 5. MyBatis 在项目里做了什么？

回答：

“MyBatis 负责数据库访问。我的 Mapper 接口定义方法，Mapper XML 写具体 SQL。程序调用 Mapper 方法时，MyBatis 会执行对应 SQL，并把查询结果封装成 User 对象。”

### 6. 你的数据库表结构是什么？

回答：

“主要是一张 `users` 表，字段包括 `id`、`username`、`password`、`real_name`、`student_no` 和 `create_time`。其中 `id` 是自增主键，`username` 设置了唯一约束，防止用户名重复。”

### 7. 登录功能是怎么判断成功或失败的？

回答：

“登录时根据用户名和密码到数据库查询。如果能查到对应用户，说明登录成功；如果查不到，返回登录页并提示用户名或密码错误。”

### 8. 为什么登录成功后可以记住当前用户？

回答：

“登录成功后，代码把用户对象保存到了 Session 里。Session 是服务器端保存用户状态的一种方式。之后访问用户列表页面时，会先从 Session 里取登录用户，如果没有登录用户，就跳回登录页。”

### 9. 注册时如何防止用户名重复？

回答：

“Service 层会先调用 `findByUsername` 查询这个用户名是否已经存在。如果已经存在，就返回注册失败。同时数据库表里的 `username` 字段也设置了唯一约束，作为数据库层面的保护。”

### 10. 修改用户信息时根据什么定位用户？

回答：

“根据用户的 `id` 定位。页面表单里有一个隐藏的 `id` 字段，提交后后端根据这个 ID 执行 update SQL，修改对应记录。”

### 11. 删除功能为什么用 ID 删除？

回答：

“因为 ID 是主键，每个用户的 ID 都唯一，用 ID 删除可以准确定位一条数据，避免因为用户名或其他字段变化导致删除错误。”

### 12. 你的项目分了哪些层？为什么要分层？

回答：

“主要分为 Controller、Service、Mapper、Entity 和 JSP 页面。Controller 接收请求，Service 处理业务逻辑，Mapper 操作数据库，Entity 表示数据对象，JSP 负责页面展示。分层以后代码更清楚，也方便以后维护。”

### 13. 如果数据库连不上怎么办？

回答：

“我会先检查 MySQL 服务是否启动，再检查 `application.properties` 中的数据库地址、用户名和密码是否正确。然后检查数据库和 `users` 表是否创建。如果是现场环境问题，可以通过 `schema.sql` 和 `data.sql` 重新初始化。”
